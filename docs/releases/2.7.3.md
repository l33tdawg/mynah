# Mynah 2.7.3

A download that stops part way is now picked up where it left off, instead of
starting the whole 670 MB again.

## What the report turned out to be

*"download seems to fail half way bro."* Checked three ways, and the published
files and the server are clean:

* the disk image downloads complete — 702,301,999 bytes — and hashes to the
  checksum published beside it;
* GitHub advertises `accept-ranges: bytes` and answers a ranged request with
  `206`, so a partial transfer is resumable at the other end;
* this Mac's own copy fetched and installed 2.7.2 in 86 seconds earlier in the
  day, and no system proxy is in the way.

**What was wrong was here.** The updater made one attempt, deleted the partial
file on the way out, and would have started from zero if it ever tried again —
and GitHub's asset link is signed with an hour on it, so on a line slower than
about 195 KB/s a single attempt cannot finish at all. A download that can never
finish is what "fails half way" describes.

## What changed

* **Each attempt asks for the bytes that are missing** (`Range: bytes=N-`), from
  whatever is already on disk, up to five times.
* **A fresh URL per attempt.** Resuming against an expired signature is a
  refusal, and a refusal loop is not a resume.
* **A `206` is appended and a `200` replaces**, decided from the status, because
  a download task always writes the response body to a file of its own — without
  this the last chunk would overwrite everything before it.
* **A refusal's body is still thrown away.** GitHub answers a refused request
  with a sentence about rate limits, and splicing that onto the front of a disk
  image is worse than starting again. The test that has asserted this since
  before there was any resume to get wrong caught this change doing it.
* The download now checks that what landed is the size the release says it
  published — the test stubs had been writing half of it, and nothing had
  noticed until the check existed.

## Validation

2,654 Mac tests executed with zero failures (18 skipped), including the four
live-node tests. The resume path was verified three ways: the installer's loop
against a stub that stops at half the file and records what each attempt asked
for, the real transport against GitHub (a ranged response extended a 1 MB file
to 2 MB rather than replacing it), and the whole suite. The Mac app is Developer
ID signed, Apple notarized and stapled, and the disk image verifies on checksum,
signature, Gatekeeper and ticket.

The bundled SAGE brain moves to **11.23.8**, which landed while this release was
being cut: two fixes about signing — `sage-gui` drains signing on an ordinary
exit rather than only on a restart, and `fence abandon` carries the peer
redelivery acknowledgement. The schema diff that every bump goes through is one
line long this time — 35 tools, none added, none removed, no description or
schema changed — so nothing the model can reach is different. Scheduled work is
unchanged from 2.7.2.
