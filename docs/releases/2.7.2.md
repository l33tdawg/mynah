# Mynah 2.7.2

The bundled SAGE brain moves to **11.23.7** — and the one change in it that
Mynah reads differently is handled before it could bite.

## The brain

Sixteen SAGE releases landed in the nine days this pin sat still, and the check
this project demands for a bump — read them against the tool allowlist, because a
SAGE release is what makes those exclusions go stale — was done **mechanically
rather than by reading prose**: the two brains' published schemas were dumped
through the appliance's own identity and diffed. One tool added, two changed,
none removed.

* **`sage_node_health` is new and is deliberately not offered to Mynah.** It is
  an operator diagnostic for an agent whose write just failed — the fence state,
  on which transaction, and how it ends. Mynah already tells you in words when a
  write did not land, and the local model's tool list sits exactly at the size it
  was measured at, so adding one is a measurement rather than a line.
* **`sage_task` now takes an id prefix.** Nothing needed to change here: Mynah
  passes the id it was given, and a prefix is strictly more forgiving.
* **`sage_backlog` is now paged**, and that one mattered. See below.

Nothing was removed or renamed, so no exclusion expired.

## The listing that is not a list

`sage_backlog`'s own description now says it: *"one call is never the whole board.
Read `total_open`, `returned`, `has_more` and `next_offset`, and page with
`offset` until has_more is false before claiming you have seen every task."*

Two things here read that reply and neither had ever been told it could be a
page: the proactive check, whose reading feeds the calendar mirror, and the board
in this window. A page taken for the whole list is the wrong direction of a
failure this product has already paid for once — on 6 August an unreadable node
deleted and re-created eleven calendar events — because every task past the first
page reads as having just been completed.

So both readers now page to the end of the list, and **refuse rather than
truncate** when they cannot get there: a list that cannot be shown to be complete
is treated exactly like a node that could not be reached, which changes nothing.

Verified against 11.23.7 on this Mac: it answers with everything it holds and
ignores `limit` — a call asking for two rows answered with five and no paging
fields at all — so in practice this is still one call, and the paging is for the
day that stops being true.

## Validation

2,650 Mac tests executed with zero failures (18 skipped), including the four
live-node tests against SAGE 11.23.7 — the same version now bundled, so the tests
and the shipped brain agree. The Mac app is Developer ID signed, Apple notarized
and stapled, and the disk image verifies on checksum, signature, Gatekeeper and
ticket.

The Even G2 companion is unchanged at 0.2.9. Scheduled work is unchanged from
2.7.1.
